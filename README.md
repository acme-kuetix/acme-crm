# acme-crm

A Kuetix package with reusable workflows and features for CRM operations: activation-code management and customer registration.

## Import

```
import github.com/acme-kuetix/acme-crm
```

## Quick Start

```bash
# Run a workflow
kue run workflows/solutions/crm/<file>.wsl

# Run all tests
go test ./...
```

`kue` is the CLI shipped by the `kue/` repo. The metarepo `go.work` must be
enabled so `acme-crm` resolves its `acme-std-*` dependencies.

## Project Structure

- **modules/crm/** - Transition package (registered into the DI container via `modules.go`)
- **workflows/solutions/crm/** - Reusable WSL workflows:
  - Activation codes: `activation-check-existing`, `activation-code-create`, `activation-code-delete`, `activation-code-get`, `activation-code-list`, `activation-code-update`, `activation-code-validate`, `activation-list-mine`, `activation-redeem`
  - Customers: `customer-profile-get`, `customer-register`, `me-products`
- **modules/di.go**, **modules/meta.go**, **modules/modules.json** - Generated by `kue update`

## Development

1. Add or edit transitions under `modules/crm/transitions/`
2. Add or edit WSL workflows under `workflows/solutions/crm/`
3. Regenerate the DI/meta cache: `kue update`
4. Run a workflow: `kue run workflows/solutions/crm/<file>.wsl`
5. Test: `go test ./...`

## Tests

```bash
go test ./...
```

## Notes

- `modules/di.go`, `modules/meta.go`, `modules/modules.json` carry `// Code generated by kueinit. DO NOT EDIT.` — regenerate with `kue update`, never hand-edit.
